# Культурный маршрут

Сервис подбора культурных мероприятий, вариант 419. Выполнил Босарев Евгений Вадимович, ЭФБО-11-24.

Афиша содержит концерты, спектакли, выставки и другие события. Посетитель создаёт аккаунт, указывает возраст, бюджет и интересы, затем открывает подборку. Подходят активные события на сегодня или более позднюю дату с хотя бы одним общим интересом, укладывающиеся в бюджет и возрастное ограничение. Сначала показываются события с большим числом совпадений, затем более дешёвые и более ранние. Рекомендацию можно сохранить, отклонить или вернуть в подборку.

## Запуск

Проверено на Python 3.12. В корне репозитория выполните:

```sh
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py load_demo
python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Команда `load_demo` добавляет учебные события с датами относительно дня первого запуска. Чтобы проверить подбор, зарегистрируйтесь, укажите возраст 20 лет, бюджет 1000 ₽ и выберите «Музыка» и «Искусство».

Для входа в панель управления создайте администратора:

```sh
python manage.py createsuperuser
```

В браузере откройте `/admin/`. Для добавления или редактирования события через основной интерфейс войдите под администратором. На странице афиши появится кнопка «Добавить мероприятие», а на карточке события — «Редактировать». Загруженные афиши сохраняются в `media/`. Чтобы снять событие с публикации, снимите отметку «В афише».

| Адрес | Что можно посмотреть |
| --- | --- |
| `/` | Главная страница и ближайшие события |
| `/events/` | Афиша с поиском, фильтрами, сортировкой и страницами |
| `/interests/` | Темы и число ближайших событий для каждой темы |
| `/recommendations/` | Личная подборка, сохранённые и отклонённые события |
| `/stats/` | Число событий и профилей, диапазон цен и статистика по интересам |
| `/admin/` | Управление данными и просмотр связей |

## Этапы проекта

| Практическая | Результат |
| --- | --- |
| ПР1 | Базовые функции проверки интереса, доступности и бюджета. |
| ПР2 | Консольный каталог, поиск, рекомендации и сохранение в JSON. |
| ПР3 | Классы `User`, `Interest`, `Event`, `Recommendation`. |
| ПР5 | Django, маршруты и страницы с данными из ПР3. |
| ПР6 | Базовый шаблон, карточки, общая навигация и CSS. |
| ПР7 | Схема SQLite, перенос JSON, 11 запросов SQL и подключение к страницам. |
| ПР9 | Модели и связи Django, миграции, перенос базы ПР7 и ORM вместо прямых запросов. |
| ПР10 | Администрирование четырёх сущностей, поиск, фильтры и просмотр связанных рекомендаций. |
| ПР11 | Формы фильтрации, редактирование профиля и событий, загрузка афиш, POST и CSRF. |

В ORM профиль посетителя (`Visitor`) связан с учётной записью Django. Интересы связаны с профилями и событиями отношениями многие ко многим. У пары «профиль и событие» может быть одна запись рекомендации. Данные ПР7 можно перенести в пустую базу Django, выполнив команды ниже после `migrate` и до команды `load_demo`.

```sh
python -m db.import_json
python manage.py import_legacy
```

Подробнее о запросах — [ПР7 SQLite и SQL](docs/pr7-sql.md). Консольные версии запускаются командами `python pr1/main.py`, `python pr2/main.py` и `python pr3/main.py`.

## Проверка

Из корня репозитория:

```sh
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
python -m flake8
python manage.py check
python manage.py makemigrations --check --dry-run
```

Тесты используют отдельную временную базу. Они проверяют консольный поиск и JSON, фильтры и пагинацию афиши, правила подбора и доступ к изменениям, загрузку изображения и его валидацию. Для вывода совпадений и всех тем карточек ORM выполняет два запроса независимо от числа мероприятий на странице.
